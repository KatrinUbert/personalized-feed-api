# Personalized Feed API

Сервис персональных рекомендаций публикаций: история взаимодействий → текстовые и поведенческие признаки → CatBoost → REST API.

Задача продукта — заменить одинаковую для всех пользователей ленту ранжированием по интересам. Решение использует содержание постов и предшествующие клики, исключает уже показанные публикации и возвращает top-K. Для пользователя без кликов работает резервное ранжирование по сглаженному CTR.

Репозиторий содержит самостоятельную реализацию на синтетических данных. Здесь нет данных работодателя, закрытых API, исторического кода или измеренного влияния на бизнес. Генератор нужен для воспроизводимого запуска и сравнения алгоритма с baseline; реальные продуктовые выводы требуют логов показов и онлайн-эксперимента.

## Стек

Python, pandas, NumPy, scikit-learn / TF-IDF, CatBoost, SQLAlchemy, SQLite / PostgreSQL, FastAPI, Pydantic, Docker.

## Быстрый запуск

Python 3.11–3.13. Команды выполняются из папки проекта.

```bash
python -m venv .venv
```

PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Linux / macOS:

```bash
source .venv/bin/activate
```

```bash
python -m pip install .
feedrec generate
feedrec import
feedrec train --cutoff 2025-01-25
feedrec recommend --user-id 7 --k 10
feedrec serve
```

Swagger UI: `http://127.0.0.1:8000/docs`.

```bash
curl "http://127.0.0.1:8000/health"
curl "http://127.0.0.1:8000/recommendations?user_id=7&k=10"
```

`generate` создаёт CSV. `import` записывает их в три таблицы SQLAlchemy и полностью заменяет прежние данные этих таблиц; используйте отдельную базу проекта. Повторная генерация с тем же seed даёт тот же датасет. `train` сохраняет модель, snapshot признаков, manifest с контрольной суммой и отчёт качества. `serve` загружает готовый snapshot, поэтому в обработке запроса нет обучения и запросов к базе.

## Данные и задача обучения

По умолчанию: 120 пользователей, 360 публикаций, 30 дней показов. У каждого пользователя есть скрытое распределение интересов; оно используется только генератором. В обучающие признаки оно не попадает. Вероятность клика зависит от совпадения интересов и темы публикации, а также от скрытого качества текста. Каждый показ содержит явный `clicked = 0/1`.

| Таблица | Основные поля |
| --- | --- |
| `users` | `user_id`, `age`, `region`, `device` |
| `posts` | `post_id`, `title`, `text`, `category`, `created_at` |
| `interactions` | `event_id`, `user_id`, `post_id`, `clicked`, `timestamp` |

Модель обучается различать клик и отсутствие клика после показа. Случайные непоказанные посты не размечаются как отрицательные примеры. Время в демонстрационном датасете трактуется как UTC.

Временная граница по умолчанию — 25 января 2025 года: события строго раньше неё входят в train, остальные — в holdout. В holdout нет подбора параметров или early stopping. Число итераций и seed задаются заранее. Для настройки на реальных данных потребуется отдельное временное validation-окно.

TF-IDF обучается на каталоге публикаций, доступном до границы train. Пользовательский текстовый профиль — сумма TF-IDF векторов прочитанных публикаций. Признаки каждого обучающего показа рассчитываются только по предшествующим событиям. События с одинаковым временем не видят метки друг друга.

Признаки модели:

- Косинусная близость текста публикации к пользовательскому профилю.
- Доля предшествующих кликов пользователя по теме.
- Число кликов пользователя и показов публикации в логарифмическом масштабе.
- Сглаженный CTR публикации: `(clicks + 1) / (impressions + 5)`.
- Возраст публикации, возраст пользователя, тема, регион и устройство.

## Оценка рекомендаций

Оценка выполняется на замороженном snapshot в момент разделения. Для каждого пользователя формируется единый пул: все доступные на эту дату посты за вычетом уже показанных. CatBoost и popularity baseline ранжируют один и тот же полный пул. Релевантные посты — публикации из этого пула, по которым пользователь кликнул в holdout. Посты, появившиеся после snapshot, в оценку не входят.

`Recall@K` — доля релевантных постов пользователя, попавших в первые K рекомендаций; итог — среднее по пользователям с хотя бы одним допустимым релевантным постом. `HitRate@K` — доля таких пользователей, у которых найден хотя бы один релевантный пост. Также сохраняются число оцениваемых пользователей, средний размер пула и число релевантных постов.

ROC-AUC и average precision считаются отдельно на фактически показанных holdout-парах из доступного каталога. Эти метрики классификации не заменяют метрики ранжирования. Выход CatBoost используется как ranking score: калибровка вероятностей отдельно не проводилась.

Результат последнего запуска хранится в `artifacts/metrics.json`; в `reports/demo_metrics.json` зафиксирован воспроизводимый демонстрационный прогон. Его результаты относятся только к синтетической среде. Непоказанные пользователю посты имеют неизвестную релевантность, поэтому offline-метрики зависят от политики сбора логов и не доказывают рост CTR или удержания.

Демонстрационный прогон 16 октября 2026 года: 17 280 обучающих показов и 4 320 holdout-показов, 120 оцениваемых пользователей, в среднем 196 кандидатов и 7,9 релевантных поста на пользователя.

| Алгоритм | Recall@10 | HitRate@10 |
| --- | ---: | ---: |
| CatBoost | 0,1960 | 0,8500 |
| Сглаженный CTR | 0,0680 | 0,4417 |

ROC-AUC на holdout-показах: 0,8837; average precision: 0,7484. Версии библиотек, параметры и отпечаток набора данных сохранены в [отчёте](reports/demo_metrics.json). Пример рассчитанной выдачи — [demo_recommendations.json](reports/demo_recommendations.json).

## Поведение API

`GET /recommendations?user_id=7&k=10` возвращает идентификатор пользователя, `as_of`, стратегию и список публикаций. Допускается `1 ≤ k ≤ 100`; неверные параметры возвращают HTTP 422.

- Известный пользователь с кликами: `strategy = catboost`.
- Новый пользователь или отсутствие кликов: `strategy = popularity`.
- Кандидатов нет: `strategy = empty` и пустой список.
- Равные оценки разрешаются по возрастанию `post_id`.
- Уже показанные публикации исключаются, включая показы без клика.

`GET /health` сообщает модель, дату snapshot и размер каталога. При отсутствии артефакта или несовпадении контрольной суммы приложение не запускается. Загружать joblib следует только из доверенного источника: формат допускает исполнение Python-кода. Контрольная сумма обнаруживает повреждения, но не подтверждает автора файла.

## Границы реализации

Это batch-система с замороженным профилем пользователя. Показ рекомендации не записывается как новое событие автоматически; историю обновляет следующий цикл импорта и обучения. Каталог и векторы находятся в памяти, все кандидаты скорятся напрямую. Для большого каталога нужны отдельный retrieval, ограничение пула кандидатов, sparse-векторы, мониторинг задержки, онлайн-сбор показов и периодическое переобучение. До продуктового применения нужны оценка на реальных логах, контроль смещений и A/B-эксперимент.
